## 1. BMO 5 — machine `1RB0LD_1LC0RA_1RA1LB_1LA1LE_1RF0LC_---0RE`

### (a) Formal statement

Wiki (BMO page, verbatim math): sequences with (a₁,b₁) = (0,5) and

- (aₙ₊₁, bₙ₊₁) = (aₙ+1, bₙ−f(aₙ)) if bₙ ≥ f(aₙ)
- (aₙ₊₁, bₙ₊₁) = (aₙ, 3bₙ+aₙ+5) if bₙ < f(aₙ)

where f(x) = 10·2ˣ − 1. **Question: does there exist i with bᵢ = f(aᵢ) − 1?** (i.e., does the machine halt; conjectured-but-unconfirmed answer: no.)

Lean (exact quote from `BeaverMathOlympiad.lean`, theorem `beaver_math_olympiad_problem_5`, @[category research open, AMS 5 11 68]):

```lean
theorem beaver_math_olympiad_problem_5 : answer(sorry) ↔
    ∀ (a b f : ℕ → ℕ), ∀ᵉ (hf : f = fun x ↦ 10 * 2 ^ x - 1)
    (a_ini : a 0 = 0) (b_ini : b 0 = 5)
    (a_rec : ∀ n, a (n + 1) = if f (a n) ≤ b n then a n + 1 else a n)
    (b_rec : ∀ n, b (n+1) = if f (a n) ≤ b n then b n - f (a n) else 3 * b n + a n + 5),
    ∃ i, b i = f (a i) - 1 := by
  sorry
```

The Lean docstring adds: found by mxdys on Aug 7, 2024; "There is presently no consensus on whether the machine halts or not"; and "The correspondence between the machine's halting problem and the below reformulation has been proven in [Rocq](https://github.com/ccz181078/busycoq/blob/BB6/verify/1RB0LD_1LC0RA_1RA1LB_1LA1LE_1RF0LC_---0RE.v)" (by ccz181078).

Equivalent 2-counter game (dyuan01's final form, the cleanest attack surface — VERIFIED equivalent, see §5):

> a(i) = 10·2^i − 1, start ⟨0,5⟩:
> - b ≥ a(i): ⟨i,b⟩ → ⟨i+1, b − a(i)⟩
> - b ≤ a(i)−2: ⟨i,b⟩ → ⟨i, 3b + i + 5⟩
> - b = a(i)−1: **halt**
>
> (⟨i,b⟩ corresponds to tape 0^∞ 01^(a(i)−2) 110 A⟩ 1^(b−1) 0^∞ in mxdys's encoding.)

### (b) Transition table (halt = F/0)

| State | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0LD |
| B | 1LC | 0RA |
| C | 1RA | 1LB |
| D | 1LA | 1LE |
| E | 1RF | 0LC |
| F | **--- (HALT)** | 0RE |

Start state A on all-0 tape; the machine reaches the (2,3) macro-config in 54 steps (proved: `init` lemma in the Rocq file).

### (c) Documented analyses

1. **mxdys, Discord, 7 Aug 2024** (discovery; quoted on the machine page). Macro-rewrite system on (a,b) := 0^∞ 01^a 110 A⟩ 1^(2b+1) 0^∞, start **(2,3)**:
   - (a, b+a+2) → (2a+3, b)   [b-coordinate ≥ a+2: "left overflow", a roughly doubles]
   - (a+b+1, b) → (2, a+4b+5) ["right overflow", a collapses to 2]
   - (a,a) → halt — "not used?" (never hit in all simulation so far)
   - (a,a+1) → (2, 2a+4) — "only used once?" (used exactly once, at the very start: (2,3)→(2,8))
   - Verified trajectory (wiki): (2,3)→(2,8)→(7,4)→(2,23)→(7,19)→(17,10)→(2,51)→(7,47)→(17,38)→(37,19)→(2,98)→(7,94)→(17,85)→(37,66)→(77,27)→(2,162)→…→(157,12)→…→(157,152)→…→(317,308)→…
   - Then his 2-counter form (start ⟨0,4⟩, a(i) = 10·2^i − 3):
     - b ≥ a(i)+2: ⟨i,b⟩ → ⟨i+1, b−a(i)−2⟩
     - b ≤ a(i)−1: ⟨i,b⟩ → ⟨i, 3b+i+7⟩
     - b = a(i)+0: halt ("unused?")
     - b = a(i)+1: ⟨i,b⟩ → ⟨i+1, i+5⟩ ("unused?")
   - **Rocq proof** (ccz181078, [busycoq BB6 branch](https://github.com/ccz181078/busycoq/blob/BB6/verify/1RB0LD_1LC0RA_1RA1LB_1LA1LE_1RF0LC_---0RE.v), 510 lines, fetched and inspected): proves `init : c0 -->* N 2 3`, each macro-rule as a lemma (`LOv`, `ROv`, `MOv`), `Halt a : halts tm (N a a)`, and the 2-counter lemmas `LOv'''`, `ROv''`, `Halt'`, `MOv'''` — i.e. **the machine↔recurrence correspondence is machine-verified** (halting itself remains open).
2. **Andrew Ducharme** (machine page): forward-simulated the representative map **33,342,087,612,867 steps** (~3.3×10¹³); not halted; both tuple entries then on the order of 10^(2.00705×10⁶).
3. **dyuan01** (machine page, quoting his Discord messages): the reparameterization chain merging the b=a(i)+1 rule into the b≥ rule (it gives ⟨i+1,−1⟩ then the ≤-rule gives ⟨i+1,i+5⟩), shifting b by +1, and redefining a(i) = 10·2^i−1, arriving at the 3-rule form quoted in §1(a). (Sligocki fixed a sign error in this section on 2026-09-03: "We want ⟨i,0⟩ = (a(i),−1)".)
4. **Classification**: machine page categories: "BB(6)", "Potential Cryptids". The Cryptids wiki page lists it among machines with "chaotic behavior" not classified as Cryptids (no tie to a named open problem like Collatz).

### (d) Structural facts

- b roughly triples per macro-step while below a(i), and a(i) doubles per index increment — the dynamics are the interplay of b ↦ 3b+i+5 versus thresholds 10·2^i−1.
- Only the *pair* (a(i)−2, b−1)-subsequence is needed: a is a pure index into powers of two. A run of consecutive ≥-steps decrements b by a(i), a(i+1), … only when b stays above successive thresholds — i.e., the halting question is a question about the base-3 expansion of iterates of b against binary thresholds.
- Fresh simulation done for this dossier (Lean recurrence, exact BigInt): first macro-states (0,5)→(0,20)→(1,11)→(1,39)→(2,20)→(2,67)→(3,28)→(3,92)→(4,13)→(4,48)→(4,153)→(4,468)→(5,309)→(5,937)→…; after ~1011 macro-steps b had 121 digits with a still 3 digits. No halt; no probabilistic/halt-odds estimate is documented anywhere for this machine.
- Negative b never occurs in the final parameterization (the +1 shift removed it — that was dyuan01's motivation).

## 2. BMO 8 — machine `1RB0LD_0RC1RB_0RD0RA_1LE0RD_1LF---_0LA1LA`

### (a) Formal statement

Wiki (BMO page): sequences with (a₁,b₁) = (10,12) and

- (aₙ₊₁, bₙ₊₁) = (aₙ − ⌊bₙ/2⌋ − 3, 3⌊(bₙ+1)/2⌋ + 6) if aₙ > ⌊bₙ/2⌋
- (aₙ₊₁, bₙ₊₁) = (3aₙ + 5, bₙ − 2aₙ) if aₙ ≤ ⌊bₙ/2⌋

**Question: does there exist i with aᵢ = ⌊bᵢ/2⌋ + 1?** (halting; wiki has a typo writing aₙ/bₙ for aᵢ/bᵢ.)

Lean (exact quote, theorem `beaver_math_olympiad_problem_8`; note value type ℤ — corrected 2026-07-26 by PR #4594 fixing issue #4591, because **a can go negative**; verified in simulation: a = −1 occurs twice in the first 10⁶ steps):

```lean
theorem beaver_math_olympiad_problem_8 : answer(sorry) ↔
    ∀ᵉ (a : ℕ → ℤ) (b : ℕ → ℤ)
    (a_ini : a 0 = 10)
    (a_rec : ∀ n, a (n + 1) =
      if b n / 2 < a n then a n - b n / 2 - 3 else 3 * a n + 5)
    (b_ini : b 0 = 12)
    (b_rec : ∀ n, b (n + 1) =
      if b n / 2 < a n then 3 * ((b n + 1) / 2) + 6 else b n - 2 * a n),
    ∃ i, a i = b i / 2 + 1 := by
  sorry
```

Lean history: added 2026-05-17 (PR #4013, Onyeka Obi), ℤ-fix 2026-07-26 (PR #4594). Unlike BMO 5, **no Rocq/Lean proof of the machine↔recurrence correspondence is cited** — the Lean entry is a transcription of the wiki statement.

### (d) Structural facts / probabilistic remarks

- mxdys's heuristic (the only "probabilistic" remark on record for this machine): visited (a,0,c) states have well-distributed log(c/a) ⇒ no quick fixpoint; simplified small-start model never halts in 10⁵–10⁸ rules.
- Fresh simulation for this dossier (Lean recurrence, exact BigInt, 10⁶ macro-steps): no halt; a ∈ [−1, 4,331,402], b ∈ [0, 4,326,825]; a took negative values on 2 steps. First pairs: (10,12) (1,24) (8,22) (29,6) (23,15) (13,30) (44,4) (39,12) (30,24) (15,42) (50,12) (41,24) … — values stay small (≪ 2⁴⁰⁰ after 10⁶ steps): the orbit is a chaotic bounded-ish walk between the two affine branches, unlike BMO 5's explosive growth. This matches mxdys's "weird": neither a clean Collatz-like blowup nor an obvious cycle.
- Branch structure: odd/even b select between 3b+8 and 3b+5 style updates; the "third rule" B(a,2a+b) → B(3a+3,b+2) fires when first ≈ half of second without the +1 offset.
- The ℤ-valuedness (occasional negative a) is a real feature, hence the Lean correction.

## 3. BMO 10 — machine `1RB0LB_0RC0LD_1LD1RE_0LA0RF_0RD1RF_0RC---`

### (a) Formal statement (wiki, verbatim math; added to BMO page by Mxdys 2026-08-01; NOT in Lean)

Σ = {0,1,#}; two-sided infinite words. Initial word w⁽⁰⁾ = ⋯10#10#10#10#0000⋯ (left-infinite repetition of `10#` + right-infinite zeros). Rewrite rules, applicable at any occurrence, in any order (no prescribed reduction order):

- `#0 → 1`
- `#100 → 000#`
- `#110 → 000#`
- `#1010 → 1010##`

A `#` is **active** if it is the leftmost symbol of an occurrence of one of the four left-hand sides (equivalently, the word beginning at that # starts with `#0`, `#100`, `#110`, or `#1010`). **Question: does there exist a finite sequence of rewrites from w⁽⁰⁾ after which the rightmost # is not active?** ("does there exist a rewrite order such that the rightmost # can no longer be rewritten?")

### (b) Transition table (halt = F/1)

| State | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0LB |
| B | 0RC | 0LD |
| C | 1LD | 1RE |
| D | 0LA | 0RF |
| E | 0RD | 1RF |
| F | 0RC | **--- (HALT)** |

### (c) Documented analyses

- **None beyond the statement itself.** No individual wiki page (search returns 0 hits), no Discord links on the BMO section, no forum threads (discuss.bbchallenge.org search negative), not in Lean. Only bbch link with status=undecided. The statement on the BMO page is the entirety of public documentation.
- Present in `BB6_holdouts_1003.txt` line 515; six other Aug-30 holdouts share its A–D rows (0RC0LD/1LD1RE/0LA0RF/0RD…) — a family of closely related machines.

### (d) Structural facts

Observations derivable directly from the rules (fresh analysis for this dossier, not from sources):
- `#1010 → 1010##` is the only rule that *creates* #'s (one # in, two #s out) and it preserves the `1010` block; the other rules *destroy* a # (turning it into 0s or deleting it into a 1).
- The rightmost # can be made inactive only if the word to its right starts with none of the four patterns — the tail after the last # would need to start with `10` followed by something other than `#0…`-triggering shapes; since the initial tail is all 0s (`#000…` is active via `#0`), activity of the rightmost # must first be destroyed by rewriting it away (`#0 → 1` deletes the last #, making the previous # the rightmost).
- Potential monotone quantities to explore: total number of #, position of rightmost #, sum of block lengths between #'s; note `#1010 → 1010##` moves the right boundary rightward while duplicating #.

## 4. BMO 11 — machine `1RB0LD_0LC0RE_1LA0RD_0RB0LC_1RC1RF_0LD---`

### (a) Formal statement (wiki, verbatim math; added to BMO page by Mxdys 2026-08-03; NOT in Lean)

Same Σ, same initial word w⁽⁰⁾ = ⋯10#10#10#10#0000⋯. Five rewrite rules, any order:

- `#0 → 1`
- `#100 → 010#`
- `#1010 → 1010##`
- `#10110 → 10101`
- `#11 → 10`

`#` active if the word at it starts with one of `#0, #100, #1010, #10110, #11`. **Question: same as BMO 10 — can the rightmost # be made non-active by some finite rewrite sequence?**

### (b) Transition table (halt = F/1)

| State | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0LD |
| B | 0LC | 0RE |
| C | 1LA | 0RD |
| D | 0RB | 0LC |
| E | 1RC | 1RF |
| F | 0LD | **--- (HALT)** |

### (c) Documented analyses

- **None beyond the statement itself** (same situation as BMO 10: no wiki page, no Discord links on the section, no forum threads, not in Lean, status=undecided).
- **Not present by exact code in `BB6_holdouts_1003.txt`** (see §0) — the closest entry (line 831) differs in rows E,F. Either it is covered by an equivalent representative or it entered the holdout lists after Aug 30; the wiki still marks it undecided (2026-09-24).

### (d) Structural facts

Fresh observations (not from sources):
- Compared with BMO 10, rule `#100 → 010#` *keeps* a # (moves it right by 2) instead of destroying it, and there are two extra destructive rules (`#10110 → 10101`, `#11 → 10`). So #/creation-destruction balance differs: BMO 11 has one duplicating rule (`#1010`), one #-preserving shift (`#100`), and three #-destroying rules (`#0`, `#10110`, `#11`).
- The `#11 → 10` rule makes short blocks collapse: any `#11` prefix is killed, so long runs of 1s directly after a # are fragile; surviving active patterns are constrained (`#10…` shapes).
- Same candidate invariants as BMO 10 (#-count, rightmost-# position, inter-# block contents), but with a different conservation profile — likely the more "shrinkable" of the two systems.

## 6. Comparison & tractability assessment (analyst's ranking)

Context that bounds all approaches: BMO1-type problems (= piecewise affine maps / LIATA) are Turing complete (forum topic 305; PAF literature), so no uniform decider exists — an elementary proof must exploit specific structure of one problem. Solved BMO problems (3, 4, 7, 9) all fell to: closed form with periodic error (4: aₙ = (3/5)(2ⁿ + period-4 correction), modular trap mod 3), residue-class/parity traps (3: powers-of-4 never hit via 2-adic valuation; 7: v₂ parity), or direct rewrite-orbit analysis (9).

1. **BMO 5 — most tractable target.** Cleanest formulation (three rules, one index, all quantities nonneg after dyuan01's shift; the machine↔math correspondence is already Rocq-verified, so a math proof converts directly into a machine non-halting proof). Structure to attack: b evolves by b→3b+i+5 while below a(i)=10·2^i−1; crossing decrements b by a(i),a(i+1),…. The halting condition b = 10·2^i−2 is a single residue/exponential-diophantine condition. Plausible routes: (i) find a mod-m invariant class of the map (b,i) ↦ … that excludes 10·2^i−2 for reachable pairs; (ii) prove b mod small numbers cycles with period incompatible with halting; (iii) understand the orbit as a base-3 expansion of the start value against binary thresholds (5 = start). Risk: 3.3×10¹³ steps simulated with no pattern published beyond growth; values grow to 10^(2×10⁶) — any invariant must be scale-free (modular/residue-class), which is exactly the style that solved BMO 4.
2. **BMO 10 — second.** Finite-alphabet, purely combinatorial rewrite system with an existential quantifier over rewrite orders (weaker/different question than reachability — closer to "is there any strategy that kills the rightmost #"). No published analysis at all, so low-hanging fruit: search for a monotone measure (e.g., a weight function on blocks) that every rule decreases/increases, or a confluence-ish normal-form argument. The rule set is tiny (4 rules) and `#1010→1010##` is the only #-duplicating rule — if one can show the duplicating rule cannot fire unboundedly often near the right end, an ordering argument may exist. Danger: the existential "some rewrite order" could make the answer YES for a boring reason (someone may just need to exhibit a strategy), i.e., possibly *easy* — worth a focused attempt first on the YES side before trying non-activity proofs.
3. **BMO 11 — third.** Same framework as BMO 10 but 5 rules with a #.-preserving shift (`#100→010#`), making the #-position dynamics richer; still zero published analysis. Same attack template as BMO 10; slightly more complex conservation profile, but the extra destructive rules (`#11→10`, `#10110→10101`) may make a killing-strategy or a weight argument easier than for BMO 10.
4. **BMO 8 — least tractable by elementary means.** ℤ-valued, genuinely chaotic bounded orbit (values ≤ ~4×10⁶ over 10⁶ macro-steps, sign changes in a), rare rule branches firing at irregular huge intervals (T=462, 41231, 6×10⁶, 4.6×10⁷, 2×10⁹, 10¹⁰, 4.7×10¹¹ — roughly geometric spacings), 8.9×10¹² rules without halt, and mxdys — the strongest analyst in the field — explicitly gave up with "this machine is weird". The halting condition (first = ⌊second/2⌋+1) sits exactly between the two branch regions, and the well-distributed log(c/a) heuristic suggests random-walk-like behavior with no closed form. A modular invariant would have to survive the 5-rule B-form with two parities — no visible residue structure. Rank last for an elementary proof.

Suggested allocation if the team splits: BMO 5 for the modular/closed-form specialist (with BMO 4's solution as the template); BMO 10/11 for a combinatorics/rewrite-systems pair, starting by trying to *win* the existential game (exhibit a rewrite order killing the rightmost #, or prove every order fails); BMO 8 only if someone wants to hunt for a Lyapunov/statistical-mechanics style argument.
